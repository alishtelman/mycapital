# MyCapital

Семейный финансовый планировщик на русском языке. Валюта KZT, календарь Asia/Almaty.

## Локальный запуск

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Откройте [localhost:3000](http://localhost:3000). Требуется Node.js 22.18+ с npm. Без переменных окружения доступен интерактивный демонстрационный бюджет. Его данные вымышлены, изменения хранятся в памяти вкладки.

### Подключение Supabase

1. Создайте проект Supabase и выполните [SQL-миграцию](supabase/migrations/001_workspace.sql) через SQL Editor или `supabase db push`.
2. Скопируйте URL проекта и publishable key из диалога Connect в `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Добавьте серверный `SUPABASE_SERVICE_ROLE_KEY`. Он используется только в API для сохранения предварительно проверенных данных и удаления аккаунта.
3. В **Authentication → URL Configuration** укажите Site URL и разрешите адрес локального запуска. Для production добавьте адрес Vercel. Включите email-авторизацию. Для отправки писем внешним получателям настройте SMTP согласно ограничениям своего проекта.
4. Перезапустите Next.js. Зарегистрируйтесь по email и паролю или запросите magic link. После подтверждения откройте «Настройки → Импорт JSON» и выберите **private/initial-data.json**. Файл находится в локальной игнорируемой папке, не входит в демо и не нужен Vercel. Не публикуйте файл и резервные копии. По умолчанию личный кабинет пуст.
5. В календаре укажите неизвестные даты обязательных расходов и дежурств. В кредитах проверьте остаток и график рассрочек. В накоплениях укажите фактические параметры вкладов, включая дату окончания БЦК и сведения об Отбасы. Для будущих госпремий добавьте МРП, поощряемую сумму и ожидаемую дату начисления.

[Официальная инструкция Supabase Auth](https://supabase.com/docs/guides/auth/quickstarts/nextjs)

### Семейный доступ

Владелец создаёт отдельный семейный бюджет в настройках и добавляет email участника. Участник входит с этим адресом и выбирает приглашённый бюджет. Участнику можно разрешить просмотр или редактирование всей рабочей области. Чтобы оставить личные данные отдельно, используйте личный бюджет и делитесь только рабочей областью с общими данными.

## Как проходят операции

- «Получил деньги» сохраняет фактическую сумму, при необходимости связывает её с календарём и открывает помощник.
- «Принять распределение» резервирует выбранные суммы. Подтверждение позиции из раздела «Бюджет» создаёт фактическое списание или перевод. Резерв уменьшается по мере подтверждения.
- «История операций» позволяет исправить сумму и дату. Остатки пересчитываются из начальных балансов и операций. Перевод создаёт одну атомарную запись с двумя сторонами.
- Графики строятся из регулярных правил, календарных исключений, сценариев, подтверждённых операций и ручных банковских параметров. Рыночные активы входят в капитал. Для появления выручки на денежном счёте оформите продажу.
- «Настройки» экспортируют JSON и CSV. JSON восстанавливает рабочую область после входа. Перед заменой экспортируйте текущие данные. CSV содержит историю операций. Календарь выгружается отдельно в ICS.
- PWA устанавливается через меню поддерживаемого браузера на HTTPS. Финансовые данные не сохраняются в кэше service worker.

## Vercel

1. Инициализируйте Git в папке проекта и отправьте исходники в свой репозиторий GitHub. Перед коммитом проверьте, что `private/` и `.env.local` исключены. Используйте приватный репозиторий для персонального проекта.
2. Импортируйте GitHub-репозиторий в Vercel, выберите Next.js и Node.js 22.x или новее. Добавьте три переменные из `.env.example`. Серверный ключ храните как секрет Vercel.
3. Запустите деплой, добавьте production URL в Supabase Auth и проверьте вход, импорт и одну тестовую операцию.
4. Для обновления прогоните проверки, экспортируйте резервную копию, примените новые SQL-миграции и отправьте коммит. Vercel пересоберёт приложение.

[Документация Next.js по развёртыванию](https://nextjs.org/docs/app/getting-started/deploying)

## Проверки

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

[SQL-тест](supabase/tests/isolation.sql) выполняется после миграции с административной ролью в тестовой БД. Он проверяет чтение владельцем, режим просмотра для участника, изоляцию постороннего пользователя и атомарность сохранения с проверкой версии. Тест откатывает изменения.

## Архитектура и ограничения

- `lib/finance.ts` — вычисления в целых тиынах, генерация событий, бюджет, распределение и прогноз. Ставки и ОП округляются для отображения.
- `components/` и `app/` — Next.js App Router, TypeScript, Tailwind, компоненты на основе shadcn/ui, Recharts и Lucide.
- `supabase/migrations/` — отдельные таблицы для сущностей, RLS и атомарная запись рабочей области с проверкой ревизии. Поля сущностей, включая детали банковских продуктов, лежат в JSONB. Подтверждённые операции и планы хранятся раздельно.
- Прогноз моделирует месячные денежные потоки на 36 месяцев. В желаемый и допустимый сроки добавляются отдельные точки расчёта. Для ОП, доходности, раннего закрытия и объединения договоров используются расчетные приближения, которые нужно сверять с выписками и договором.
- Недатированные правила расходов включены в месячный прогноз, а помощник резервирует обязательства по событиям с известной датой. Неизвестные поступления не включаются до настройки.
- Для защиты данных проверяйте сетевой сценарий регистрации, восстановление и RLS на своём проекте Supabase перед загрузкой личных данных. Локальные проверки не требуют подключения к облачному проекту. Автоматических подключений к банкам нет.

## Платёжный календарь и закрытие месяца

- **Главная** показывает, сколько из фактических незарезервированных денег можно потратить в день и сколько доступно для накоплений. Платёж на день зарплаты обеспечивается заранее. Недатированные обязательства уменьшают безопасный остаток до уточнения дат.
- **Бюджет → Обязательные платежи** задаёт периодичность, ближайшую дату, крайний срок, способ оплаты и интервалы напоминаний. Редактирование отдельного события в календаре меняет только этот платёж. Резерв блокирует доступную сумму. «Оплатил» создаёт одну фактическую операцию и использует связанные резервы.
- **Календарь → Денежные потоки** показывает ежедневную оценку вплоть до года. Автосписания остаются на заданной дате. Для остальных платежей дата рекомендуется с запасом до срока и с поправкой на выходные. Государственные праздники и время фактического банковского зачисления в прогноз не входят.
- **Могу ли я себе это позволить?** сравнивает три варианта бюджета. После применения покупка сохраняется как запланированная. Минимумы гибких категорий сохраняются. Дата квартиры оценивается по точкам месячного прогноза.
- **Отчёт за месяц** показывает движения средств и накоплений. Для изменения ОП и суммы банковских процентов используйте ручную сверку. При закрытии месяца можно перенести свободные лимиты категорий на следующий месяц и проверить остатки счетов. Перенос не создаёт поступления денег.

### Напоминания и обновление

Настройте время и календарный запас в **Настройки → Напоминания**. Часовой пояс — Asia/Almaty. Интервалы задаются отдельно для каждого обязательного платежа. Консервативный режим исключает непредсказуемые доходы из доступного денежного потока до подтверждения. Чтобы получать напоминания вне MyCapital, импортируйте **Календарь → Экспорт ICS** в Apple Calendar или Google Calendar. В файл включены сигналы VALARM. Проверьте, что выбранный календарь сохранил их и что у него разрешены уведомления. После переноса платежей обновите импорт.

Внутренние уведомления пересчитываются при открытии и в открытой вкладке. MyCapital не отправляет Web Push при закрытом приложении. Внешние напоминания может показывать календарь, в который импортирован ICS. На бесплатном Vercel Hobby каждая задача Cron запускается максимум раз в сутки и с точностью до часового окна. Это подходит для ежедневных дайджестов, но не обеспечивает доставку в выбранную минуту. [Vercel Cron Jobs](https://vercel.com/docs/cron-jobs/usage-and-pricing)

Обновление использует дополнительные необязательные поля в существующих записях JSONB и не требует новой SQL-миграции. На действующем проекте разверните новый код. Для новой базы по-прежнему нужна `001_workspace.sql`. Старые импорты и связи с единичным резервом поддерживаются. Перед обновлением можно выгрузить резервную копию в JSON.
